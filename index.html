SECURITY-MINDED RENDERING

Untrusted HTML deserves
careful boundaries.

Rendering user-controlled markup can expose infrastructure when browser automation is unrestricted. In the prototype, page JavaScript is disabled and browser requests are intercepted. The production Docker image now passes a PDF and network-isolation test in GitHub Actions. We’re checking which production hosts can provide the namespace permissions the renderer needs.

01JavaScript disabledDocument markup is rendered without executing page scripts.

02Remote requests blockedExternal URLs and local network requests are blocked in the renderer.

03Scoped credentialsAPI keys can be created and revoked independently.

04Quota controlsMonthly usage is reserved atomically against plan limits.

We’ve made good progress on the renderer: the production Docker image now passes a PDF and network-isolation test in GitHub Actions. That test uses a disposable CI container with the namespace permissions Bubblewrap needs. The remaining challenge is the production host: Railway does not expose the required container security controls, so we’re keeping the hosted API offline until a compatible environment has been tested. This work has not been independently audited. Please don’t send personal, confidential or production documents.
