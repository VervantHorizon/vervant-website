PUPPETEER · PDF DEBUGGING

How to troubleshoot Puppeteer PDFs that are blank, clipped or inconsistent

A PDF can be technically valid and still be wrong: a chart is missing, a custom font falls back, a background disappears or the last rows of a table are clipped. Work through the rendering pipeline in order instead of adding arbitrary sleeps.

1. Confirm which CSS media type you are printing

page.pdf() uses the print CSS media type. That means rules inside @media print apply, while screen-only layout rules may not. If the page looks right in a normal browser tab but wrong in the PDF, inspect print styles first.

@page {
  size: A4;
  margin: 12mm;
}

@media print {
  .screen-only,
  .no-print {
    display: none !important;
  }

  .keep-together {
    break-inside: avoid;
  }

  .new-page {
    break-before: page;
  }
}

Use page.emulateMediaType('screen') only when you deliberately want screen styles in the PDF. It disables print media styles, which can also disable your print pagination rules. Usually, leaving Puppeteer's default print media is the safer starting point.

2. Wait for the document, not an arbitrary number of seconds

networkidle0 can help when a document loads assets over the network, but it is not a universal “page is ready” signal. A chart may render after an API call, a client-side template may finish later, or a font may still be loading. Prefer an explicit readiness marker that your own page controls.

await page.setContent(html, {
  waitUntil: 'networkidle0',
  timeout: 20_000,
});

// Your app sets this after its data and charts are ready.
await page.waitForSelector('[data-pdf-ready="true"]', {
  timeout: 10_000,
});

await page.evaluate(async () => {
  await document.fonts.ready;

  await Promise.all(
    Array.from(document.images, image => image.decode()),
  );
});

If you own the page, set data-pdf-ready="true" only after asynchronous data, charts and other visual components have finished. A fixed delay can hide a race on your laptop and fail again under load.

3. Make page size and background choices explicit

Choose one source of truth for paper dimensions. When your HTML owns page sizing through @page, set preferCSSPageSize: true. Otherwise, pass a format such as A4 or Letter directly. Also remember that background graphics are not printed unless you request them.

const pdf = await page.pdf({
  printBackground: true,
  preferCSSPageSize: true,
  // The CSS @page rule above owns paper size and margins.
  waitForFonts: true,
  timeout: 30_000,
});

When using CSS page size, avoid also setting a conflicting format, width, height or PDFOptions margin. Alternatively, let Puppeteer own the paper settings with format: 'A4' and a margin object, and remove the corresponding size and margin declarations from @page. For exact colors, add -webkit-print-color-adjust: exact to the elements that need them and test the result in the PDF viewer your customers actually use.

4. Check fonts and image failures separately

A successful PDF response does not prove that every asset loaded. For each font, confirm that the file URL resolves, the browser is allowed to request it and the declared family/weight matches the CSS. For images, check their HTTP status, MIME type, dimensions and whether they have finished decoding.

For a repeatable production render, prefer bundled, versioned assets over arbitrary third-party URLs. If users can supply HTML, do not let the browser fetch any URL by default; remote resources can change output and create server-side request risks. See the HTML-to-PDF security guide.

5. Find layout overflow before changing the scale

Clipped content often comes from a fixed height, overflow: hidden, a wide table or an oversized image—not from Puppeteer itself. Inspect elements that cross the printable width, test long text and use real multi-page fixtures. Avoid shrinking the whole document with scale until you know what is overflowing; it can make small text unreadable.

@media print {
  html,
  body {
    height: auto;
    overflow: visible;
  }

  table {
    width: 100%;
    border-collapse: collapse;
  }

  thead {
    display: table-header-group;
  }

  tr,
  img {
    break-inside: avoid;
  }
}

break-inside: avoid is a hint, not a guarantee. A row or image taller than the printable page may still need to split or be redesigned.

6. Keep a small regression fixture

Test more than a one-line title. Keep a sample document that includes a long address, a multi-page table, non-ASCII text, a missing optional image, long descriptions, a final total and a page footer. Check the page count and inspect the actual pages after every Chromium or CSS change.

  • Compare the rendered PDF, not only the HTTP status.
  • Record the Chromium and Puppeteer versions used for the test.
  • Set bounded navigation, font and PDF-generation timeouts.
  • Log a request ID and safe error category; do not log full customer HTML or PDF contents.
